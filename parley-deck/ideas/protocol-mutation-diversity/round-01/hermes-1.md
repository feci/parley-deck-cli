## Summary

Mechanism-design lens: no blind-random mutation operator is warranted for this protocol at n=4 / 2 generations. The GA analogy (§1, §6 of ga-notes.md) breaks on exactly the dimensions that matter: no automatic numeric fitness (fitness = human judgment), no cheap individuals (one round = minutes + bill), no crossover splice of two agent proposals, and convergence is frequently *correct* (agreement ≠ failure). Section 5 of the notes is decisive: for LLMs mutation is a *learned proposal operator with semantic priors*, not uniform noise; a proposal that reduces to "raise temperature" must answer §5 directly — it does not, and is rejected.

A mutation-like mechanism CAN be warranted, but only in structured, non-random, gated forms. Below I enumerate the concrete operator shapes that could be considered (each named, each matched to what's already shipped), then recommend the only one that is defensible: a **semantic-role perturbation** (forced adversarial lens) gated on stagnation and instrumented per §15.6(b) / §15.3, with a recorded seed. Even that, I rate as inherited (already partially covered by the roles: map and round-01 independence), not constraint-forced new machinery.

The removed steelman clause (§7 of notes, superseded 2026-08-29 by `protocol-generation-bias`) is NOT re-proposed here. Its function (force consideration of the strongest rejected position before signoff) is now carried mechanically by §15.6(a) (enumeration duty, machine-validated) and §15.6(b) (correlated-agreement disclosure). A separate adversarial-artifact clause duplicates that carrier and adds a file that does not reach consensus. If diversity is wanted, the mechanism should perturb the *generation* of proposals, not add a retrospective file.

Null result is legal: after enumerating existing alternatives below, "no mutation operator is warranted as new machinery" is the recommendation. The mechanism the user describes — "a bit of randomness so some participant comes up with a completely different angle" — is captured more precisely by reusing the existing diversity infrastructure (roster model-family spread + independent round-01 + advisory roles: lens + stagnation-triggered lens swap) rather than inventing an operator.

PRIMARY references verified from this repo: `parley-deck/COOPERATION.md` §15.1–15.7 (§15.6); `reference/ga-notes.md` §1, §3, §4, §5, §6, §7; `00-prompt.md` roles map; `protocol-generation-bias/FINAL.md` (ratified 2026-08-29); `openviking-context-structure/FINAL.md` (2026-08-31, unanimous convergence on shared prior); `~/.parley/agents.toml` (deep / max for all but hermes-1 at high).

## Proposed approach

Named operator, if adopted (not recommended as new machinery):

- **Name:** `semantic-role-perturbation` (constraint-forced: builds on the roles: lens mechanism; inherited: uses existing file structure).
- **What is perturbed:** the assigned advisory lens (`protocol fit` / `skeptic` / `mechanism design` / `measurement`) in `00-prompt.md` `roles:` block. Not the participant identity, not the prompt text, not model config (temperature is refused per §5), not a synthetic adversary file.
- **When it fires:** ONLY when a stagnation predicate is met. Predicate (inherited from existing round structure): same participant issues the same recommendation category across two consecutive rounds with no adopted `ALT-` and no `DISPUTED` claim. Not every round; not globally; not on `fast` (fast must stay ≤1 cycle per §4.0).
- **Perturbation rule (structured, not random):** forced adversarial swap. Example: mechanism-design participant is reassigned `skeptic` lens; measurement participant gets `protocol fit`; protocol-fit gets `measurement`. The swap is deterministic (hash of idea-slug + round-number as seed, recorded in `consensus.md`) so replay is reproducible (§15 provenance / determinism constraint). Not bit-flip noise.
- **Cost:** one extra model call per affected participant, within the existing round — no new round, no new file type, no new artifact class. Costs are bounded: at most 2 of 4 participants perturbed in any round (to preserve quorum); never on the last round before `FINAL.md`.
- **Measurement (per user request):** (a) count of adopted `ALT-` entries post-perturbation vs. pre-perturbation, per idea; (b) rate of `DISPUTED` claims (increased disagreement is the target, not nonsense); (c) `FINAL.md` must contain `## Diversity evidence` naming the perturbation seed and whether it produced a new adopted alternative or a new `DISPUTED` claim. If neither, the mechanism is recorded as inert for that idea — no fabricated diversity claim.
- **Failure mode (named, per prompt requirement):** the perturbed participant argues a position it does not hold. Mitigation: the reassigned lens is advisory-only (§0 roles: "advisory only — does not change quorum, signoff weight, artifact ownership"); the participant's canonical `round-NN/<agent-id>.md` must start with `## Lens (perturbed): <new lens>` and quote the prior round's recommendation verbatim before responding. Any deviation is a §15.5 position-change report failure, detectable by review.

Rejected alternatives within the operator family:
- **Temperature / randomness increase** — rejected per ga-notes.md §5 (inefficiency of random mutations in large spaces; mutation must be a learned proposal operator with semantic priors). Random perturbation of a 220,115 B prompt is close to worthless.
- **Synthetic adversary file (new `adversarial.md`)** — rejected: duplicates the removed steelman clause (§7); the mechanism was replaced by §15.6(a) + (b) and `protocol-generation-bias`. Re-introducing it requires justification that those carriers are insufficient; none is given.
- **MAP-Elites archive change to `FINAL.md` format** — rejected: would change what `FINAL.md` is (from single best proposal to best-per-niche). A protocol-level change; out of scope for a single mechanism idea without a meta-change (§7 of COOPERATION.md).
- **FunSearch island reset on stagnation** — partially adopted in principle (reset = role-perturbation), but full island model (sub-populations, behavioural hash collapse) rejected: no behavioural descriptor is defined for deliberation artifacts; hash-collapsing variants requires a descriptor we don't have.

**Recommendation:** do not add new machinery. Use the existing three-layer diversity mechanism: (1) model-family spread in roster (`claude-1` Anthropic / `codex-1` OpenAI / `hermes-1` Thinking Machines Lab inkling / `kimi-1` Moonshot — PRIMARY, ~agents.toml and roster); (2) independent round-01 (island model, PRIMARY, 00-prompt.md); (3) advisory roles: lens (PRIMARY, 00-prompt.md roles:). If stagnation is detected (no new `ALT-` across two rounds), the facilitator applies a deterministic lens-swap within existing structure, recorded as seed. This is inherited infrastructure, not new protocol.

## Concerns / open questions

- **§5 of ga-notes.md is decisive and unaddressed by any "randomness" proposal.** Any mechanism that does not name a semantic prior for its perturbation has not engaged the literature this user asked us to read. The user proposal itself uses the word "randomness"; the next design step must translate that to a named, structured operator. Not done = proposal rejected.
- **The analogy cost (§6) is severe.** No fitness function; selection is preference; n=4 / 2 generations; no crossover splice; convergence often correct (`openviking-context-structure` — all four independently converged; the result was correct and had to be recorded as shared prior, not evidence, per §15.6b). Adding mutation when agreement is usually right injects artificial disagreement that must then be refuted — cost without benefit unless stagnation is actually occurring. PRIMARY evidence: `FINAL.md` for openviking (2026-08-31) shows unanimous round-01 convergence; no artificial divergence would have helped.
- **Correlated agreement (§15.6b) is the real mechanism, and it is already adopted.** `protocol-generation-bias/FINAL.md` (2026-08-29) records that the facilitator circulated both a mandatory-correction list (a conform-instruction that suppresses diversity) and a mandatory 16-item negative-findings list (a diversity-suppression structure); five files converged. The diversity problem is not absence of mutation — it's presence of structured suppression. Adding a mutation mechanism without addressing suppression (the existing §15.6 carriers do address it) treats the symptom, not the mechanism.
- **Measurement risk (§4 failure mode).** A mutated participant that argues a position it does not hold produces an artificial `DISPUTED` claim. If `FINAL.md` treats any `DISPUTED` as diversity evidence, diversity is trivially maximized by injecting nonsense — exactly what the user warns against ("diversity trivially maximised by producing nonsense"). The proposed instrument (`## Diversity evidence` + seed + adopted-`ALT-` count) prevents this, but only if the review cycle actually reads it. Not mechanized.
- **Stagnation predicate definition.** The trigger (same recommendation category across two rounds, no adopted `ALT-`, no `DISPUTED`) is not defined in `COOPERATION.md`. It is proposed here; if adopted, it needs to be added to the protocol as a defined gate (meta-change, §7). This is the one component that genuinely requires a protocol edit if adopted — the rest is inherited.

## Risks

- **R1 — Artificial disagreement degrades quality.** A forced adversarial lens produces an argument the participant does not hold; the following round must refute it. Cost: extra round time + model tokens; risk: the artificial argument is adopted accidentally (no fitness function to filter it). Mitigation: instrumented measurement (seed + adopted-`ALT-` + `DISPUTED` tracking); if adopted-`ALT-` does not rise after two perturbations, the mechanism is disabled for that idea and recorded inert. Not adopted as mandatory; advisory only.
- **R2 — The mechanism duplicates what `protocol-generation-bias` already solved.** Leg 1 (enumeration) + Leg 2 (evidence exchange) + Leg 3 (disposition) already make hidden alternatives visible and recorded. Introducing mutation without demonstrating that these carriers leave diversity gaps unaddressed risks a redundant mechanism. PRIMARY evidence: `FINAL.md` shows adoption of all three legs; no gap is documented.
- **R3 — Randomness proposal ignores §5 (SECONDARY from notes; PRIMARY from file).** Any final recommendation that cites "random mutation" without a named semantic prior violates the literature this round was asked to read. The file must either (a) adopt a structured operator with named priors (lens-swap), or (b) explicitly reject mutation and explain via §5 and §6. This file does (b) as primary recommendation, (a) as conditional adoption.
- **R4 — Measurement fabrication.** Without the `## Diversity evidence` instrument, any increase in round count or `DISPUTED` claims can be claimed as "increased diversity" without proof of quality preservation. The instrument is proposed but not mechanized; absence of mechanism = absence of proof = risk of false claim.
- **R5 — Protocol-change cost.** If any mutation mechanism goes beyond existing infrastructure (new gate definition, new artifact type), it requires a meta-change (§7 COOPERATION.md) with attended publish and full quorum. The null result avoids this cost entirely. The conditional lens-swap avoids it unless the stagnation-gate definition is adopted — in which case a separate meta-idea is triggered.

The user's original idea — "a bit of randomness" — is rejected in that form; its intent (diverse angles) is redirected to the existing three-layer mechanism (roster diversity + round-01 independence + roles: + stagnation-gated lens-swap) which already ships.
