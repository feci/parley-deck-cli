## New concerns / questions

The four `forget` mappings reveal a category error worth preserving in the final record:

- bounded prior-round context is **transmission**;
- ledger state changes are **owner-authorized lifecycle and context compilation**;
- `superseded-by:` is **artifact versioning/discoverability**;
- protocol byte reduction is **subtractive maintenance**.

Treating them as one imported mechanism would recreate the terminology fragmentation this idea is
trying to diagnose. The final should use the Parley operation names and state that cognee's verb was
only a prompt for inspection.

The v1.43.1 deletion is now the decisive implementation question. A successor must determine whether
the ledger failed because its semantic invariant was unprovable, because its implementation was
defective, or both. Until then, “already ratified” is not evidence that recovery is feasible.

For consolidation, an inventory must distinguish three cases: true duplicate normative statements,
an authoritative rule plus a deliberately non-normative navigational reference, and distinct rules
that share vocabulary. Only the first should be merged. This avoids both hermes-1's valid warning
about fuzzy matching and kimi-1's risky non-use heuristic.
