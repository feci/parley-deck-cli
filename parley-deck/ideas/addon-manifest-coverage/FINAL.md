## What ships

Manifest coverage for every packaged skill, a generic source anchor so the proof works for the
core as well as the add-ons, and three consequential integrity fixes the rounds uncovered along
the way. No new status strings, no exit-code policy change, no new trust model.

## The four defects, and what closes each

**D1 — foreign-install false red (the reported bug).** `doctor` exits 1 and reports five of six
skills `malformed` after a foreign installer copies them. Closed by shipping
`parley-addon.json` for all six units (F1) plus the `sourceRoot` anchor (F3).

**D2 — marker-present gutted add-ons report `valid` (false green).** Our own installer, marker
retained, add-on reduced to a single `SKILL.md`: `valid`, `managed: true`, `doctor` exit 0.
Closed by F1 alone — once the source ships a manifest the marker records
`manifest: {aggregate, sha256}` and the existing `declared`-object path catches the gutting. No
code change on the managed path.

**D3 — legacy markers keep the false green across the upgrade.** A pre-fix install records
`manifest: false`; after this change that install still reports `valid` and exit 0 when gutted.
Closed by F4.

**D4 — the core's required-file list is shorter than what it installs.** A natively installed
core survives deletion of `plugin.json`, `agents/openai.yaml` and
`references/WORKED_EXAMPLES.md` with `doctor` exit 0, `valid` and zero problems. Closed by F5.

## Binding fixes

**F1 — manifests for all six.** `parley-deck`, `parley-design`, `parley-design-check`,
`parley-tracker`, `parley-worktrees` join `parley-bidding`. Generated by
`scripts/build-addon-manifest.js`, committed to the repository, `--check` wired into `npm test`
and `prepack`. No `runtime` block for the five; none declares an interpreter floor.

**F2 — coverage is mandatory, not opt-in.** Drop the `CORE_SKILL_NAME` exclusion from
`listAddons()`; the no-argument default enumerates every `skills/*/SKILL.md` directory, and a
skill without a manifest is a `--check` failure. Without this a seventh skill repeats D1
silently.

**F3 — `sourceRoot` on every unit.** `unmanagedButVerified` reads `unit.sourceRoot` instead of
reaching through `unit.addon`. Four sites: the core unit, the add-on expected loop, the
on-disk-not-selected loop, and the no-context fallback (which stays without a `sourceRoot` and
behaves as today). The predicate names no skill.

**F4 — legacy-marker migration.** In `manifestProblems`, `declared === false` together with
`sourceHasManifest` reports that the marker predates this skill's manifest and the install must
be re-run. This extends the already-ratified precedent one branch above it at
`installer.js:2280`. **The user approved the consequence on 2026-08-01**: everyone with a
pre-fix install sees a red `doctor` until they re-run `install`. The message must name the
repair, and `CHANGELOG.md` must explain it.

**F5 — derive the core's required-file list from the copy plan.** Replace the four hand-written
per-target lists with a list computed from `PAYLOAD_ENTRIES` plus target-specific entries;
optional entries (`README.md`, `LICENSE`) stay optional. Catches deletion, not modification —
the same limit the current list has.

**F6 — documentation in the same commit.** `README.md:79` and the `CHANGELOG.md` "Known limits"
section both claim `parley-bidding` is the only skill shipping a manifest. Both become false.

## Fork decisions (binding)

- **No per-target "exact expected layout" manifests for the core.** Proposed by codex-1 in
  round 1, withdrawn by its author in round 2. The installed native core carries no manifest,
  so the packaged core manifest is consulted only as source-side proof on the unmanaged path,
  where the tree is a verbatim copy of `skills/parley-deck/`.
- **Do not add `parley-addon.json` to `PAYLOAD_ENTRIES`.** It would make the native core a
  superset that its own source manifest flags as `unexpected`. Guarded by a regression.
- **No `volatile` manifest entries**, and no verifier that re-implements the installer's
  `gemini-extension.json` rewrite. A manifest that re-derives installer logic is a second
  source of truth.
- **No new status strings and no exit-code change.** `valid-unmanaged` already exits 0.

## Verification — every item run, none asserted

Regressions split into two kinds, per Amendment 1.1. Conflating them is an error.

**Fix-proving — each MUST fail at `23a9856`:**
1. foreign verbatim copy of all six → six `valid-unmanaged`, `managed: false`, `doctor` exit 0;
2. native install, markers retained, each add-on gutted to `SKILL.md` → `malformed`, exit 1;
3. a genuine `markerSchema: 2, manifest: false` fixture on an add-on whose source now ships a
   manifest → flagged re-install-to-validate, then repaired by re-running install;
4. native core minus a file the current required-list omits (e.g. `plugin.json`) → `malformed`;
5. source drift — edit a payload without regenerating → `--check` fails and install preflight
   writes nothing.

**Survival guards — each MUST pass before and after:**
6. unmarked gutted copies stay `malformed`, manifest kept and manifest deleted (B3);
7. ownership unchanged: a `valid-unmanaged` fleet blocks install and uninstall without
   `--force`, and no marker is synthesized;
8. the natively installed core does **not** carry `parley-addon.json`, asserted per target.

Plus: the full existing suite on both interpreters. hermes-1's report that it passes with the
anchor patch alone was reproduced by nobody and must not be relied on.

## Invariants that may not be weakened

- A tree gutted to `SKILL.md` is unhealthy, with or without a marker.
- Proof is anchored to the packaged source, never to the manifest sitting beside the installed
  payload.
- `valid-unmanaged` is health, not ownership. Install and uninstall still refuse it without
  `--force`, and neither synthesizes a marker.
- Manifests are defect detection, not tamper resistance. No argument for or against a design
  may rest on an attacker who can already write to the payload.

## Definition of done

All eight verification items green, full suite green on both interpreters, `--check` green,
`README.md` and `CHANGELOG.md` corrected, version bumped, and the release published to all five
channels per standing project practice.

## Deferred, recorded, not silently dropped

1. Byte-level integrity for the core's **managed** path — after F5 the core catches deleted
   files but still not modified ones.
2. A foreign tree from a different package revision stays `malformed` even when internally
   intact; accepting historical manifests needs a packaged digest history.
3. A natively installed core whose marker was deleted reports `malformed` although its bytes
   are correct — the native tree carries the root extras and no manifest, so it cannot match
   the packaged source layout.
4. `parley-addon.json` and schema `parley-addon/1` keep an "add-on" name now that the core
   carries one.
5. Existing tests encoding current file counts and `manifest: false` behaviour need individual
   review, not a bulk edit.
