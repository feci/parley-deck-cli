## Position changes since round 1

**CHANGE 1 — `EFFECTIVE-MATCH` (boolean) is withdrawn in favour of codex-1's `STATUS` column with a closed vocabulary.** My boolean answered "is something wrong" but not "what". `STATUS` with codes (`model-drift`, `not-installed`, `unmapped`, `auto-off`, `effort-unknown`, `masked-by-env`, `metadata-unknown`, `stale-snapshot`) answers both in the same width and generalizes to future divergences without adding columns. claude-1 made the same change; the underlying requirement I cared about (divergence visible in the row, not buried) is met either way.

**CHANGE 2 — `FAMILY` is renamed `ADAPTER`.** codex-1's term is more precise: "adapter" is the actual codebase term (`[roster.<id>] adapter`), and "family" collides with `MODEL-FAMILY` — two columns with "family" in their name answering different questions is a readability bug. I keep my round-1 argument that this column is the launch/dispatch key distinct from AGENT; only the label changes.

**CHANGE 3 — `SOURCE` column added in round 1 is withdrawn.** I did not propose `SOURCE` in round 1 (claude-1 and kimi-1 did), but I would have wanted it. codex-1's `roster show --explain AGENT` plus a `sources` object in JSON is strictly better: per-field provenance is too wide for a 12-column table, and the question "where did this value come from" deserves a dedicated view, not a cramped cell. I adopt `--explain`.

**CHANGE 4 — `--scope session|machine` is withdrawn in favour of `--scope deck|machine`.** I documented in round 1 that `session` is nominal (it maps to `parley-deck/agents.toml`, not a per-session store — `PRIMARY`: `internal/app/roster.go:383-389`). kimi-1 reached the same conclusion independently. Between codex-1's `local|global` and kimi-1's `deck|machine`, I choose `deck|machine` because `local` is ambiguous (machine-local? project-local?) and `deck` is unambiguous — it is the `parley-deck/` directory. `session` stays as a hidden alias for compatibility.

**CHANGE 5 — `MODEL` fallback rule is hardened.** My round-1 rule: parse the model token out of `HeadlessArgs`, fall back to `spec.Model` when no model flag is present. claude-1 and codex-1 are right that falling back to a declared value in the same cell is how the current lie is told. I adopt codex-1's rule: when the adapter cannot establish an effective model, the cell reads `unknown` (or an explicit `cli-default (~/.codex/config.toml)`), never the declaration. For codex and kimi today that is the honest answer — neither launch passes a model flag (`PRIMARY`: `parley agents list` headless lines show `codex exec …` with no `-m`, `kimi -p {prompt}` with no `-m`).

**CHANGE 6 — the model-argv fix mechanism.** My round-1 proposal was `roster set --model` rewriting `headless_args` per-family. claude-1's placeholder substitution (`{model}`/`{effort}` in HeadlessArgs, resolved by the runner) is simpler and reuses the existing `{root}`/`{prompt}` mechanism (`PRIMARY`: `runner.go:1101-1103` handles `{root}` and `{prompt}` today; adding `{model}` and `{effort}` is the same code path). codex-1's structured bindings and legacy normalizer are the general form. I adopt the synthesis: built-in specs use placeholders, the runner substitutes them, and a legacy normalizer handles deck overrides that hardcode model literals in `headless_args`. See "Current proposal" §6.

**CHANGE 7 — sync semantics.** My round-1 sync was a copy-down (write §2 IDs' mappings to deck). I withdraw it in favour of kimi-1's additive/source-aware approach over codex-1's rebase. See @codex-1 response for the reasoning.

## Current proposal

Converged position, adopting others' work where it beat mine:

1. **Canonical table** — 12 columns, frozen, identical in text and `--json` (schema version 1, golden tests):
   `AGENT`, `ADAPTER`, `STATE`, `INSTALLED`, `MODEL`, `MODEL-FAMILY`, `MODEL-COMPANY`, `ROUTE`, `EFFORT`, `SPEED`, `AUTO`, `STATUS`.
   `DISPLAY-NAME` leaves the table (derived, redundant, and today self-contradicting). Deliberately excluded: `VERSION`, `SANDBOX`, `APPROVAL`, `TIMEOUT`, `HOME`, `BACKEND` — these are `agents list` diagnostics, not roster facts. `SOURCE` is excluded from the table; per-field provenance lives in `roster show --explain AGENT` and the JSON `sources` object.

2. **`MODEL` and `EFFORT` are effective launch values or `unknown`** — never a declaration wearing the effective cell. For adapters with no model/effort flag in argv (codex, kimi today), the cell reads `cli-default (~/.codex/config.toml)` or `unknown`. Divergence surfaces as `STATUS=model-drift` or `STATUS=effort-unknown`.

3. **`modelmeta` resolver** — CLI-owned, versioned, tested registry. Strip known gateway prefixes (`litellm/`, `openrouter/`) into `ROUTE`; map the inner producer/model segment to `MODEL-FAMILY` and `MODEL-COMPANY`. Unknown returns `unknown` + `metadata-unknown` in `STATUS`. The registry ships per release; no per-deck hand-maintenance. `ROUTE` reflects only what the model id encodes, not the adapter's internal routing — hermes' `glm-5p2` shows `ROUTE=unknown` because the LiteLLM routing is in `~/.hermes/config.yaml`, invisible to parley.

4. **Verbs** (all appear in `parley --help`):
   - `parley roster show [--scope deck|machine] [--all] [--json] [--explain AGENT]`
   - `parley roster update AGENT --scope deck|machine [--adapter A] [--state active|inactive] [--model M] [--effort E] [--speed S] [--dry-run] [--yes]`
   - `parley roster sync [--dir DIR] [--dry-run] [--yes]` (global → deck ONLY, additive/source-aware per kimi-1)
   - `parley roster add <family> [--as <id>]` (writes `[roster.<id>]` mapping + prints §2 row to ratify; does not edit §2)
   - `roster init` becomes a deprecated alias for `roster sync --mappings-only`.
   - Preview/dry-run is the default; `--yes` applies. `--yes` is refused for breaking membership changes when `roster_change_policy = "confirm-breaking"`; a second confirmation (`--confirm-breaking` or interactive) is required.
   - `--scope deck` writes to committed `parley-deck/agents.toml`; `--scope machine` writes to `~/.parley/agents.toml`. `session` stays as a hidden alias for `deck`.

5. **Sync semantics** — additive and source-aware (kimi-1): for every active §2 member, pin machine-sourced values (adapter mapping, model, effort, speed) into `parley-deck/agents.toml`. A field whose winning source is already the deck is never touched. This makes the deck self-contained without destroying deliberate per-deck pins. Sync never adds §2 rows (§14.2); IDs in `[roster.*]` but not in §2 are reported with a clear instruction, not auto-added. Sync never copies local values upward.

6. **Model-argv fix — placeholder substitution + legacy normalizer (in scope for this idea):**
   - Built-in `HeadlessArgs` change from embedded model literals to `{model}` and `{effort}` placeholders (e.g. claude: `["-p", "--model", "{model}", "--effort", "{effort}", …]`).
   - The runner substitutes `{model}` and `{effort}` from the resolved config layer, the same way it substitutes `{root}` and `{prompt}` today (`runner.go:1101-1103`).
   - A legacy normalizer handles existing deck `headless_args` overrides that hardcode model/effort literals: it identifies the model/effort flag positionally and replaces the stale value with the resolved value, reporting `legacy-argv-normalized` in `--explain` output. Users do not need to edit existing decks.
   - For adapters with no model flag (codex, kimi), no placeholder is used; `MODEL=cli-default` or `unknown`.
   - This is a live behavior change: decks pinning `claude-opus-5[1m]` will start actually launching it. Ship with a changelog entry, a preflight probe, and the `STATUS=model-drift` marker visible one release *before* injection ships (kimi-1's mitigation).

7. **Session = immutable run snapshot, not a scope** (codex-1). At run creation, write a secret-free immutable roster snapshot and `roster_revision` hash into `run.json`/`run.created`. The live process and all later phases use the same snapshot. `sessions inspect` reports `stale-snapshot` when the live roster differs. A user who wants the new roster starts a new run.

8. **§2 stays authoritative for membership, drops model details.** §2 table keeps Agent ID, Workspace dir, Role. Model/effort/speed details leave the Role column and move to config (rendered by `roster show`). This is a protocol content change that ships with this idea's FINAL.md (see concern #1 — flag if you believe it needs a separate meta idea).

9. **Migration is prompted, not automatic.** The 17 rosterless decks: `roster sync --dry-run` detects "no §2 roster" and prints a bootstrap instruction (`roster init` / `roster add`). The 17 decks naming retired `antigravity-1` (and 3 `gemini-1`, 1 `agy-1`): `roster show` renders them with `STATE=inactive` (once the inactive set is wired up), excluded from default participants. The user runs `roster update <id> --state inactive --scope deck` or edits §2 to remove them. No automatic roster modification (§14.2). The CLI surfaces the drift; the human acts.

10. **Skill/CLI boundary.** The skill prints `parley roster show` output verbatim and never parses config or maintains a second table. The skill's session-start habit is `parley roster sync --dry-run`. The skill's deck-bootstrap instructions must be corrected: picks are persisted through `roster update`, not through `meta/headless-agents.local.json` (which the CLI does not read). The skill text, CLI behavior, top-level help, and golden tests ship in the same release.

Open for round 3 or signoff: concerns #1 (§2 authority / protocol change), #3 (agy built-in spec scope), #4 (roster_change_policy confirmation mechanism), and #5 (effort placeholder scope). Concern #2 (hermes gateway invisibility) is a documentation question, not a blocker.
