## Position changes since round 1

1. **Gate filenames: per-OS encoded names → universal encoding on every OS plus a legacy read-fallback.** I concede this to claude-1 and kimi-1. My round-1 argument (Unix decks keep byte-identical names; Windows has no legacy to break) was true but one-sided: it ignored decks shared across machines — this very workspace lives on a cross-machine shared volume, and a deck round-tripped between a macOS and a Windows checkout would diverge on-disk. New facts I verified this round make the universal design cheap: product code never parses an edge ID back out of a filename — the only consumers of the name are `GatePath` itself (`gate.go:105`), `SaveGate` (`:110`), `LoadGate` (`:131`) — and `SaveGate` derives its staging name as `tmp := path + ".tmp"` (`gate.go:115`), so encoding inside `GatePath` fixes the `.tmp` failures kimi-1 pointed at by construction. Identity lives in the gate JSON body; the on-disk name is cosmetic.
2. **Directory durability: documented no-op → real-mechanism attempt first, evidence-decided fallback, never silent.** The round-2 brief applies the owner's constraint correctly: documentation alone must not silently replace a real implementation or a refusal. My round-1 "documented nil" leaned on documentation too heavily. New position (kimi-1's direction): `sync_windows.go` opens the directory via `CreateFileW` with `FILE_FLAG_BACKUP_SEMANTICS` and write access and calls `FlushFileBuffers`; a hosted diagnostic cycle determines whether that succeeds on windows-latest/NTFS. If it deterministically fails `ACCESS_DENIED`, the choice between a user-visible refusal (which would make trajectory verification unusable on Windows) and a reviewed, disclosed deviation is surfaced to the owner as an explicit line in FINAL — not decided silently by the implementer. File-handle fsync stays mandatory and unchanged.
3. **ACL allow-set: {user, SYSTEM, Administrators} → owner-only.** I adopt claude-1's verify rule and ratify kimi-1's exclusion of `BUILTIN\Administrators` (admin-can-take-own is the same residual as root on Unix and is documented, not granted). I extend the exclusion to SYSTEM: nothing in parley runs as SYSTEM, Defender reads via backup privilege regardless of the DACL, and a silent SYSTEM grant is a broader effective audience than `0700` encodes. Because creation now sets a protected DACL (`PROTECTED_DACL_SECURITY_INFORMATION`) containing exactly one owner ACE, the create→verify round-trip is self-consistent. I keep my round-1 refinement: verification evaluates *effective granted trustees* via `GetNamedSecurityInfo` (so pre-existing stores are judged by who can actually read, not by a protected-flag), and the refusal string stays sentence-stable with the offending trustee appended. FAT/exFAT/no-ACL volumes: refuse.
4. **Product shell dependency enters scope, and I self-correct my round-1 framing.** `SELF-CORRECTION` (§15.1): my round-1 fixture section said "product's only `/bin/sh` is build-tagged `internal/procctl/terminal_unix.go`" — literally true for the string `/bin/sh` but presented in a context implying product source was POSIX-free. That implication was wrong, exactly as claude-1's own F.5 self-correction states. `PRIMARY` at HEAD: product non-test code invokes `sh -c` at `internal/evidence/execute.go:118`, `:122` (the embedded POSIX `criterionSupervisor` program, `:100-116`, with `trap`/`wait`/`kill -0` semantics) and `internal/app/driver_impl.go:266` (the `checks:` gate). Claude-1's discovery is confirmed and the missing-shell contract (named, actionable refusal when `exec.LookPath("sh")` fails, plus a Windows test that pins the refusal path rather than the runner's incidental `sh.exe`) is now part of my proposal.
5. **Block-ID validation added to my scope.** Claude-1's W-NAME extension is confirmed by my own read: `manifest.go` validates block IDs only for non-empty and uniqueness (`:157-165`), and `BlockWorkspace` interpolates `blockID` verbatim into a path (`executor.go:28-30`) — a traversal surface on every OS that Windows merely exposed. I include it, with a compatibility counterproposal (see Responses).
6. **Encoding primitive: `net/url.PathEscape` adopted as base only.** I reproduced claude-1's execution: `block-a->block-b` → `block-a-%3Eblock-b`, but `":"`, `"CON"`, `"end."` pass through untouched. So the encoder needs an explicit `:` escape plus a reserved-device-name/trailing-dot guard, and manifest-level ID validation remains the primary defense (encoding is defense in depth).
