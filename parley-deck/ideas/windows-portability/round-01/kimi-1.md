## Summary

The Windows leg fails on a small number of genuine product defects — a POSIX-permission privacy guard that can never pass on Windows (71 hosted failures), Windows-illegal pipeline-gate filenames, and POSIX-assumed locking/sharing/synchronization semantics — plus a broad but shallow test-portability debt (shell-script fixtures, chmod-unreadable fixtures, CRLF, HOME-only env, path-separator assumptions) that currently hides how much of the product actually works on Windows. None of it requires weakening privacy or skipping applicable tests: `golang.org/x/sys v0.36.0`, already a direct dependency, ships every Win32 primitive needed for real ACL verification, Job-Object tree kill, and handle-based process attribution. I propose five ordered workstreams (compile blocker + fixture portability → gate filenames → fsutil/lock semantics → ACL privacy → procctl attribution), each re-validated on the hosted matrix, with acceptance exactly as the prompt states: unfiltered green windows-latest plus still-green macOS/ubuntu on the released commit, no new suppression, and explicit documentation that hosted x64 Server runners are the only Windows evidence.

## Proposed approach

Sequenced so early workstreams unblock measurement of later ones. All product changes build-tag-scoped or behavior-identical on Unix; the reviewed Linux repairs in this base (U1 acp drain, U2 procctl cmdline poll, refusalGit identity) are preserved untouched — verified present at HEAD.

**WS-A — Unblock and see clearly (test-side + one workflow step).**
1. W4 compile blocker: split `internal/evidence/tree_report_test.go` so the FIFO/socket adversarial test lives in a `//go:build unix` file. FIFOs and unix sockets genuinely have no Windows filesystem-entry counterpart, so a Unix-tagged variant with a recorded reason is a *legitimate* inapplicability exclusion — but only after an honest attempt at a Windows-side equivalent (candidate: an NTFS junction/reparse point the digest must reject; whether hosted runners allow unprivileged junction creation is an open empirical question, listed below). If no equivalent exists, the exclusion reason is reviewed individually per the prompt.
2. W5/W6 fixtures: replace `#!/bin/sh` and extensionless-script fixtures with the test-binary re-exec pattern (`os.Executable()` + env/arg guard) — already the in-repo precedent (`internal/acp/spawn_test.go` `TestStderrObserverChild`, the budget reservation fixture process invoked at `review_test.go:405`). Where a discoverable executable file is the point (fake `parley-deck-skill`), emit `.bat`/extensionless per `runtime.GOOS`. Fix `app_test.go:155`'s unchecked assertion to `t.Fatalf` on missing payload so a fixture failure fails one test, not the package — this is what allows `wait`/`usage` tests to execute on Windows for the first time.
3. W8: fixtures set `USERPROFILE` (and `HOME`) via `t.Setenv`; verify product config resolution uses `os.UserHomeDir()` semantics rather than reading `HOME` directly (agents/configmodel failures show empty resolution on Windows).
4. W9: worktree fixtures build absolute paths through `filepath` (volume-aware) instead of literal `/repo`; normalize path comparison at inventory boundaries (`filepath.Clean`/slash normalization decision documented).
5. W10 CRLF, two layers: (a) add `.gitattributes` pinning `eol=lf` for text/source so hosted and contributor Windows checkouts carry the same bytes as other OSes; (b) product parsers that fail closed on content must be CRLF-tolerant anyway — the drift guard's embedded-default anchor match (`drift_test.go:100` failure) and consensus template block extraction compare a build-time-embedded file against an on-disk file a *user's* git may have converted, so normalization is a product requirement, not a CI convenience. (a) does not substitute for (b).
6. ACP drain-guard tests (`spawn_test.go:146/166`): the U1 product fix is correct and stays; the *tests* assume the anonymous pipe holds the 8 KB second write while the copier is gated — true on Linux (64 KB), false on Windows (default buffer is smaller), and the hosted failure message names exactly this. Restructure the handshake: READY first, then parent-paced chunked writes, keeping the gating-observer race pin intact.
7. Add a cross-compile guard step to the ubuntu leg: `GOOS=windows go build ./... && GOOS=windows go vet ./...`. This catches Windows *compile* regressions (the Mkfifo class) pre-merge. It is labeled honestly: compile-only evidence, never execution evidence.

**WS-B — W2 persisted gate filenames.** Keep `EdgeID()` (the logical identifier inside gate JSON) unchanged; change only the on-disk filename encoding to a Windows-legal, deterministic, collision-free mapping applied uniformly on **all** OSes for new writes (no per-OS persisted-name divergence — this workspace itself lives on a cross-machine shared volume). The atomic-write staging name must use the same encoding (hosted failures are on the `.tmp` file). Add a read-fallback that recognizes legacy `->` names so pending gates written by older binaries remain resolvable; write path emits new names only. This is the "persisted-name compatibility decision" the prompt requires to be documented.

**WS-C — W3 Windows file semantics (product).** Audit and fix every open/read/replace/sync that assumed POSIX semantics, under explicit design rules: (i) read-only inspection of a file another component may hold locked (lock-origin, identity probe) uses a Windows open with full sharing (`FILE_SHARE_READ|WRITE|DELETE`) via `x/sys/windows.CreateFile`, since Go's `os` package does not expose share flags; (ii) never rename/replace/delete over an open handle — ledger/snapshot publication closes descriptors before `MoveFileEx` (existing `internal/fsutil/replace_windows.go` already uses `MOVEFILE_REPLACE_EXISTING|MOVEFILE_WRITE_THROUGH`; the fix is handle discipline around it); (iii) directory durability on Windows needs `FlushFileBuffers` on a handle opened with `GENERIC_WRITE|FILE_FLAG_BACKUP_SEMANTICS` — implement `syncDir` for Windows instead of inheriting the `Access is denied` failure seen at `verification_test.go:368`; (iv) the existing `LockFileEx` byte-range lock at offset 1 MB (`internal/budget/lock_windows.go`) stays as the exclusion primitive — the hosted failures are sharing/open-path conflicts, not lock-acquisition conflicts. Unix paths stay byte-identical.

**WS-D — W1 snapshot privacy on Windows (product, security surface — the heart of this idea).** Real ACL verification, fail-closed, no weakened check. Design: a `//go:build windows` implementation of the private-store guard that (1) *creates* the snapshot store with an explicit protected DACL granting full control to exactly the current-user SID and LocalSystem (`WinLocalSystemSid`), inheritance blocked (`SE_DACL_PROTECTED`); (2) *verifies* by `GetNamedSecurityInfo` → `SECURITY_DESCRIPTOR.Control()` (must show protected) → `DACL()` walk: every access-allowed ACE's trustee SID must be in the allow-set, any other trustee or any inherited allowance refuses with the same error contract as today ("snapshot store must be a private real directory"); (3) applies the same verification to files (`snapshot.go:544` site). I propose **excluding** `WinBuiltinAdministratorsSid` from the allow-set — including it would be exactly the "weaker privacy" the prompt forbids; the residual (an admin can take ownership, like root on Unix) is documented instead. The Unix guard is untouched. Read-back verification (create → immediately re-query → refuse on mismatch) doubles as the self-check against struct-layout mistakes in hand-built ACLs.

**WS-E — procctl on Windows: real attribution and tree kill, replacing the refusal where a real mechanism exists.** `procctl_windows.go` today refuses durable kill and reports no facets; the hosted `durablekill_test.go:41` failure is the *test* expecting Unix behavior on top of that refusal. Proposal: (1) spawn under a Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` so `KillGroup` becomes `TerminateJobObject` — a genuine tree kill, stronger and more honest than the current `taskkill /T /F`; (2) attribution facets from process handles: `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` + `GetProcessTimes` creation time (the pid+creation-time pair is the Windows analogue of Linux `/proc` start-time and survives as a cross-restart identity facet) + `QueryFullProcessImageName` for the command facet; (3) facets with no honest Windows mapping (session-leader semantics) get a designed, user-visible refusal, with tests asserting the refusal contract instead of Unix behavior. Every primitive is already in the pinned `x/sys` (locators in Existing alternatives). Durable-kill scope on Windows (what can and cannot be attributed after a reboot) is defined in FINAL, not improvised.

**Acceptance and honesty envelope (unchanged from prompt, restated as design constraints).** Full unfiltered `go test ./... -count=1 -timeout 45m` green on windows-latest, macOS, ubuntu at the released commit; participant review that no suppression (`-run` filters, skips, retries, `continue-on-error`) entered the workflow; each inapplicability exclusion reviewed individually. Stated coverage limits in CHANGELOG/docs: hosted `windows-latest` = x64 Server image, `runneradmin` context, `core.longpaths=true`, Git-for-Windows line-ending conversion as observed; **no Windows ARM64 execution evidence** (the arm64 asset remains built-but-unexercised); no native-desktop, FAT/exFAT, or non-admin-host validation. Windows-experimental label removal and the held winget PR proceed only on that green, per the prompt's release gates.

## Existing alternatives

Per §15.6(a): for each mechanism the proposal builds by hand, what the platform/toolchain already ships, with locators. `go.mod:9` pins `golang.org/x/sys v0.36.0` as a direct dependency; module-cache paths below are `$(go env GOMODCACHE)/golang.org/x/sys@v0.36.0/windows/`.

- **ALT-1 — Snapshot privacy guard.** Hand-rolled today: `Perm()&0077` at `internal/trajectory/snapshot.go:162/:544`. Platform ships: `GetNamedSecurityInfo` (`security_windows.go:1442`), `GetSecurityInfo` (`:1430`), `SetNamedSecurityInfo` (`zsyscall_windows.go:1260`), `SECURITY_DESCRIPTOR.DACL/.Control/.Owner` (`security_windows.go:1209/1185/1241`), `ACL`/`EXPLICIT_ACCESS` types (`:893/:1083`), `StringToSid`/`SID.String` (`:180/:232`), `CreateWellKnownSid` with `WinLocalSystemSid=22`, `WinBuiltinAdministratorsSid=26` (`:449/:347/:351`), `LookupAccountName` (`zsyscall_windows.go:1016`). Gap, stated precisely: ACL *construction* primitives (`InitializeSecurityDescriptor`, `SetSecurityDescriptorDacl`, `AddAccessAllowedAce`, `SetEntriesInAcl`, SDDL string conversion) are **not** wrapped in x/sys v0.36.0 — verified by grep of the module cache; creation therefore needs a thin internal `advapi32` wrapper via `NewLazySystemDLL` (`dll_windows.go:284`) over stable Win32 ABI. Rejected alternatives: `github.com/hectane/go-acl` (third-party wrapper over the same advapi32 — a new dependency for what one internal file wraps); `icacls` subprocess (parses localizable text output, fragile, extra process per verify); Go stdlib (`os.Chmod` documents that on Windows "only the 0o200 bit … is used" — `go doc os.Chmod`; no stdlib ACL API exists — scoped null, source: stdlib `os` docs).
- **ALT-2 — Cross-process locking.** Hand-rolled: `internal/budget/lock.go` + `lock_windows.go` (LockFileEx byte-range, already present). Platform/dep ships: `LockFileEx`/`UnlockFileEx` in x/sys (in use), named mutexes `CreateMutex`/`CreateMutexEx` (`zsyscall_windows.go:1846/1837`). Third-party: `github.com/gofrs/flock` (Windows via LockFileEx) — rejected: new dependency, and the hosted failures are share-mode/open/rename conflicts, which no lock-acquisition library fixes; the fix is handle/share discipline (WS-C), not a different lock.
- **ALT-3 — Process tree kill / attribution.** Hand-rolled today: `taskkill /T /F` (`internal/procctl/procctl_windows.go`). Platform ships: Job Objects — `CreateJobObject` (`zsyscall_windows.go:1828`), `AssignProcessToJobObject` (`:1706`), `SetInformationJobObject` (`:3287`), `TerminateJobObject` (`:3391`); attribution — `OpenProcess` (`:2915`), `GetProcessTimes` (`:2548`), `QueryFullProcessImageName` (`:2998`). No new dependency; Go stdlib has no job-object API (scoped null — source: `os/exec` exposes only `SysProcAttr` fields, which carry no job handles on Windows).
- **ALT-4 — Stderr drain ordering.** Hand-rolled: copier goroutine + `p.wg` (post-U1, correct). Toolchain alternative: assign `cmd.Stderr = io.Writer` and let `os/exec` drain inside `Wait` — the safe pattern `internal/evidence/execute.go` already uses — rejected *for acp specifically* because the ACP observer must stream non-blockingly during the live session, which the in-`Wait` drain cannot do. No third-party equivalent applies; the hosted failure was the test's pipe-capacity assumption, not the product ordering.
- **ALT-5 — Test fixtures needing an executable.** Hand-rolled `/bin/sh` scripts today. Toolchain/in-repo pattern: test-binary re-exec (`os.Executable()` + guard arg) — precedent in-repo at `internal/acp/spawn_test.go` (`TestStderrObserverChild`) and the budget reservation fixture process; stdlib precedent `os/exec` `TestHelperProcess`. Zero new machinery, portable to every OS. `.bat` generation only where file-discovery semantics are the test subject.
- **ALT-6 — Line endings.** Options: repo `.gitattributes` (`* text=auto eol=lf` or scoped) vs parser-side CRLF normalization vs workflow `git config core.autocrlf false` pre-checkout. Workflow flag alone rejected: it does nothing for a *user's* Windows checkout, and the drift guard compares embedded-vs-disk bytes on user machines. Proposal adopts `.gitattributes` **and** parser normalization; neither alone suffices (evidence: `hardening_test.go:456` CRLF content from a git-checkout fixture; `drift_test.go:100` anchor-miss on the same leg).
- **ALT-7 — Gate filename encoding.** Hand-rolled `from+"->"+to` (`internal/pipeline/gate.go`). In-repo precedent for safe persisted names: §12.7 idempotency keys are sha256 digest-prefixed filenames. Options: sanitize (encode `->`) keeping readability — proposed; full hash names — rejected (loses human/debug value that gates, as human-facing HITL artifacts, need); keep names and refuse pipeline blocks on Windows — rejected: pipelines are a shipped product feature, refusal here would be weaker product behavior without a security justification (contrast ALT-1, where refusal is the fail-closed privacy posture).
- **ALT-8 — Windows CI coverage.** Options: hosted `windows-latest` only (proposed acceptance) vs adding emulated/cross runners (no execution fidelity) vs buying native hardware (out of scope for this idea). ## Concerns / open questions

1. **Administrators-SID policy** in the DACL invariant (WS-D): I propose owner+SYSTEM only. This is a security-policy choice peers should explicitly ratify or counter-propose; the alternative (allow `BUILTIN\Administrators`) matches many tools' defaults but weakens the guarantee the Unix 0700 check encodes.
2. **Hosted-runner ACL capability**: can the `runneradmin` context on `windows-latest` set protected DACLs on temp dirs, and does the default `%TEMP%` ACL even allow a "private" verdict to be constructed? Expected yes, but a spike probe (one build-tagged test asserting create→verify round-trip) should run on the hosted leg before WS-D's full design lands. `PRIMARY`-verifiable only on hosted hardware.
3. **Unsupported-entry digest test on Windows** (WS-A.1): is there a deterministic, unprivileged filesystem entry on the hosted image that `TreeDigest` must reject (junction? dangling reparse point?)? If none, the exclusion record must say so plainly rather than faking equivalence.
4. **CRLF mechanism attribution**: the hosted log proves CRLF bytes appear on the Windows leg (`hardening_test.go:456`) and that the drift-guard anchor missed (`drift_test.go:100`); that the cause is the runner image's git autocrlf setting is my **inference** (`RECALL`-grade mechanism over `PRIMARY` symptoms) — implementation should confirm the image's `core.autocrlf` before finalizing the `.gitattributes` scope.
5. **W3 blast radius**: how many write paths touch files that may be locked/open elsewhere (ledger, lock-origin, effects, runstate)? The 11 hosted sharing failures sample it; a systematic audit during WS-C may find more. Scope growth here is the most likely schedule risk.
6. **Durable-kill semantics on Windows** (WS-E): pid+creation-time is strong but the full Linux facet set (boot id, pgid, session-leader) has no 1:1 mapping; FINAL must define the Windows attribution contract explicitly rather than implying parity.
7. **Deck portability of persisted names**: this deck's lock/ledger/gate files already exist on POSIX machines; WS-B/WS-C rename/encoding decisions must not strand existing decks (read-fallbacks), and this very workspace sits on a shared volume whose Windows filesystem semantics (if ever mounted from Windows) are unknown — worth one documented sentence in FINAL.
8. **Pipe-capacity semantics** on Windows are under-documented across Server/client SKUs; WS-A.6 must remove capacity assumptions entirely rather than retune sizes.

## Risks

- **Validation ceiling (the standing one):** all Windows evidence is hosted x64 Server runners; no native hardware, no ARM64 execution, no non-admin/desktop/ReFS/Dev-Drive coverage. Mitigation: state the envelope in CHANGELOG/docs; never extend claims beyond the hosted leg; keep the experimental label until green, per the prompt.
- **Hand-wrapped advapi32 ACL construction** (ALT-1 gap): struct-layout or flag mistakes could produce ACLs that are permissive (privacy hole — the worst outcome here) or corrupt. Mitigation: verification-by-readback built into the creation path (refuse if the effective DACL ≠ intended), property-style tests comparing intended vs effective DACL, and review focus on this file above all others.
- **Mandatory-lock surprises** (WS-C): Windows byte-range locks and share modes interact with editors, indexers, AV scanners on real user machines in ways hosted runners won't show. The design keeps fail-closed posture (a lock failure refuses rather than proceeds unprotected) — but user-environment lock behavior is validated only on hosted runners; document that.
- **`.gitattributes` addition** rewrites line endings repo-wide on next checkout — one-time diff noise, and it touches `parley-deck/` records including the embedded protocol default; must land as its own reviewed commit, not smuggled into a fix commit.
- **Gate-name migration** (WS-B): a deck with pending `->` gates read by a new binary must resolve them; missing the fallback silently stalls pipelines. Test the mixed-name deck explicitly.
- **Test-portability sweep masks product bugs**: fixtures ported carelessly could stop exercising the product path they existed for (e.g., a re-exec helper that skips the real launcher). Each ported fixture must name the product behavior it still pins; reviewers refute that mapping.
- **Scope/sequencing**: 100 distinct failing tests across 14 packages invite one giant unreviewable diff. The WS-A→E ordering exists to keep each hosted re-validation attributable; collapsing them is a review-integrity risk, not a speed gain.
- **Unix regression**: every product change must be build-tag-scoped or provably behavior-identical on Unix; acceptance includes macOS+ubuntu still green at the released commit, and the preserved U1/U2/refusalGit repairs in this base must not be re-litigated into this diff.
