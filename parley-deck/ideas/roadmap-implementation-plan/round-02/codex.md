## Summary

After reading round 1, I would revise my first-slice recommendation. My `repo-map-mvp` proposal is still important, but Claude and Gemini are right that the immediate bottleneck in current Parley Deck runs is growing artifact context, not repository discovery. Hermes's resilience focus is also important, but error/rate/credential guards become more useful once we know which generated artifacts and prompts are moving through the system.

The convergence point should be a deterministic context-efficiency foundation: generate compact round indices and add a reusable artifact sanitizer/pruner. This is a small, local slice that directly supports trajectory compression, future memory, later prompt packing, and review ergonomics.

## Proposed approach

Revised ordered roadmap:

1. `round-index-artifact-pruning`: after a round completes, generate `round-NN/_index.md` from participant artifacts and add a reusable sanitizer that removes hidden reasoning blocks and trims noisy metadata for context use. Do not mutate original artifacts.
2. `repo-map-mvp`: add deterministic repo maps with file tree plus Go symbol extraction using standard-library parsing first.
3. `context-pack-wiring`: use round indices, sanitized artifacts, repo maps, and strict budgets in later round/review/signoff prompt builders.
4. `error-classifier-redaction`: classify agent failures and add explicit redaction helpers for secrets in generated context.
5. `hooks-mvp`: add conservative pre/post run hook points after typed errors and context artifacts exist.
6. `local-memory-insights`: build opt-in local insights over round indices and finalized ideas.
7. `direct-sdk-backend-pilot`: only later, if provider prompt caching or semantic cache becomes worth the migration cost.

First slice details:

- Add a small internal package or runner-local module for context artifact helpers.
- Implement `SanitizeArtifactForContext` with deterministic removal of common hidden-reasoning fences such as `<think>...</think>`, `<thought>...</thought>`, `<thinking>...</thinking>`, and similar explicit blocks.
- Implement a round index writer that scans `round-NN/<agent>.md`, preserves agent/date/frontmatter metadata, extracts section headings, and captures compact first-paragraph summaries.
- Write `round-NN/_index.md` after `RunRoundOne` completes, including skipped/failed agents where possible from runner results.
- Keep `_index.md` generated by the runner/facilitator, not owned by any participant.
- Tests should cover sanitizer behavior, deterministic index ordering, failed/skipped agent rows, and no mutation of source artifacts.

## Concerns / open questions

- The sanitizer must not pretend to be security redaction. Secret redaction should be a separate explicit slice with different tests and failure semantics.
- If index generation fails, the round should probably still complete but surface a warning/result entry. Failing a successful agent round because an auxiliary index could not be written would be frustrating.
- We should not add LLM summarization yet. This slice should stay deterministic.

## Risks

- Index content could become too lossy if we over-trim. The first version should keep headings and first paragraph snippets rather than trying to infer meaning.
- Regex-based hidden-reasoning removal can be brittle. Keep the supported patterns explicit and tested, and do not market it as complete provider reasoning control.
