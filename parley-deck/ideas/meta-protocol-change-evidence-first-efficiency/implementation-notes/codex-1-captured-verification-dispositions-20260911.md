# Charge-bound execution of retained source

## Outcome and acceptance boundary

The captured-source execution API now binds the complete original charged
attempt to its retained before/after archives and executes original material
criteria on reconstructed worktrees in AB/BA order. A dirty failed patch can be
compared after the live files change again, while retaining its real original
commit and dirty observation. The implementation does not manufacture clean
commits, stage the live files, or rewrite the user's index/HEAD/branch refs.

This is internal execution integration toward AC-B2. It does not launch a model,
authenticate the selected verifier, persist an independent helper receipt, grant
continuation or resolve any attempt. All currently captured attempts remain
pending. Independent model/helper invocation, durable request/receipt publication,
complete trajectory evaluation and review/recovery remain binding work.

## Frozen request and exact reproduction

FreezeCaptured reads the existing shared cycle/trajectory authority, including
complete ledger coverage and every referenced archive. The request pins the
policy hash, original attempt hash, exact charge, actual invocation, sequence,
implementer, selected non-implementer verifier, original source observations,
archive references and all original criterion hashes. Missing terminal/source,
an unchanged file-tree or a self-verifier refuses. The captured-worktree kind
has a distinct request hash domain from clean-commit comparisons. It does not
pretend same-HEAD dirty output is a committed patch.

OpenCaptured rechecks that request against current durable authority, restores
both archives into fresh private directories outside Git, and attaches separate
local copies of original Git object history. The copies use --local,
--no-hardlinks, --no-checkout and an empty template. They are detached at the
actual recorded commits, with an index read from each recorded commit. No new
commit is created. Each reproduced root must match its original complete Source:
commit, file-tree digest, dirty bit and status digest. The copied objects are
separate files, not hardlinks into the live object database.

Object storage is checked before and after copying against 512 MiB and 100,000
entries. Alternates, symlink/special object entries, unreadable or excessive
storage refuse. A parent inside Git is rejected before allocating directories.
Failure cleans up only the newly allocated verification directory. Every API
instance owns its own temporary roots; the original worktree is never a target.

These archives retain source files, not arbitrary historical staged index blobs
or a separate Git-object backup. A staged-state mismatch or unavailable recorded
commit therefore refuses exact reproduction instead of substituting current
index data, another commit or a clean status. This is an explicit remaining
recovery/retention gap. The clone preserves original objects and recorded Source
identity, not a byte-for-byte historical capture of all refs, repository config,
index extensions or external execution dependencies. The material criteria and
recorded observations remain the scope of the comparison; there is no universal
causation claim or authentication against consistently fabricated same-UID state.

## Execution and assessment

VerifyCaptured requires the exact ordered original raw criteria supplied at
runtime and compares their hashes before executing anything. Around each actual
AB/BA command it rechecks the original durable request/charge/source authority
and both reproduced Source observations. The existing RunCriterionDetailed path
retains format-aware status, exact output/command hashes, execution counts and
actual process outcomes. An observed post-execution source digest is recorded;
the expected digest is never substituted after drift.

Every workspace handle is single-use. A repeated call cannot overwrite the
outcome of that helper invocation. This is local handle protection, not yet
cross-process durable replay prevention: a parent must retain the request and
receipt for every actual verifier launch. Interrupted or source-changing commands
return their partial observations with an error; failed evidence does not become
a clean comparison.

AssessCaptured uses the same criterion assessment as the existing clean-commit
API. Stable pass-to-fail material evidence confirms regression; an unrelated
source change with stable passing scope confirms no regression. Pre-existing
failures remain inconclusive. Opaque, skipped, incomplete, self-attributed,
changed-tree or contradictory evidence cannot confirm an outcome. Clean-commit
request validation and ordinary pass-only completion attestation remain intact.
No API here changes charged counts, completion state or quorum.
