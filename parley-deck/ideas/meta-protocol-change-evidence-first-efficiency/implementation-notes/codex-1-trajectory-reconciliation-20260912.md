# Durable trajectory reconciliation and continuation

## Result and authority

A completed independent comparison can now be reconciled with its original
charged patch. Reconciliation re-reads the retained private parent request/result,
successful instrumented terminal, original shared ticket and complete helper
journal. It recomputes the assessment from the retained AB/BA executions and
requires the current original named criteria, exact commands/order and quorum.
Changing or losing retained evidence refuses on every later state boundary.
The parent result remains observation evidence; it does not authorize another
patch on its own. No caller-provided outcome or filtered patch list is accepted.

`trajectory reconcile --dir DIR --idea IDEA --run VERIFIER_RUN` returns a read-only
preview. Apply adds `--sha256 PREVIEW_SHA --yes`. Identical simultaneous applies
and exact replay preserve one resolution. Changed previews, another original run
or an omitted earlier charge refuse. `trajectory history` derives all ordered
assessments from the complete original charged history.

The first second-consecutive-regression trigger stays recorded after corrective
work. Another consecutive regression requires an acknowledgment covering that
new sequence. Inconclusive evidence remains visibly inconclusive after an
operator allows another attempt. The separate pending-action list can clear;
the historical assessment and its pending-evidence indicator do not become pass.

## Continuation and original source

`trajectory continue --dir DIR --idea IDEA` previews a separate clean promotion
and any required acknowledgment. The actual source must be clean, contain exactly
the original captured after-source material bytes and descend from that original
HEAD. Parley does not commit, stash or discard it. Apply requires the exact preview
hash, a unique decision ID/reason, platform attendance and the corresponding
`--acknowledge-review` or `--acknowledge-inconclusive` flags when pending.
An unneeded acknowledgment flag also refuses instead of asserting an event that
the preview did not require.

The recorded acknowledgment is a cooperative operator assertion, not a model
review or participant-authored signature. There is one continuation per sequence;
exact replay cannot issue another grant. A separate archive/reference supplies
the next clean before-state while every original dirty after-record, attempt
hash and budget charge stays unchanged. The frozen policy remains version 2;
state with resolution/continuation records uses version 3. Older writers must
reject it rather than ignore transition history. Untransitioned version-2 state
remains readable; digest-only version 1 retains its explicit recovery refusal.

Applying or replaying a decision returns its exact preview from the same guarded
operation. An older exact replay after later patches returns the original
preview/hash and does not depend on a new promotion of the latest dirty source.

The common manual/grouped/driver/resume observer requires reconciled history,
required acknowledgments and exact source continuity before another reservation.
Every new patch still consumes its existing budget. Failed work remains charged;
neither command extends ceilings, resets the epoch nor closes an implementation.
Completion still requires the latest confirmed no-regression outcome, all action
gates resolved and the exact current source, followed by ordinary current-tree
whole-implementation evidence and protocol signoffs.

## Remaining limits and obligations

Original roots, shared guard origin and all retained evidence must remain
readable. Lost parent results, failed helper tickets, unchanged-source attempts,
missing snapshots/staged index/Git history, orphan reservations and moved origins
still need explicit recovery. These commands neither reconstruct missing history
from today's source nor automatically retry a model. Same-UID fabrication remains
outside this cooperative attribution boundary. Existing POSIX process-control
limits, arbitrary daemonized sessions and abrupt outer-runner death are unchanged.

No real model invocation or actual operator activation occurred in these tests.
Current-source participant acceptance and complete live launch coverage remain
required. AC-B2 and the overall audit are incomplete. Safe guard-origin migration,

14/30-day follow-ups remain binding. The historical quorum and unanswered provider,

## Current result: stable material revalidation

even when its initial descriptor reports no timestamp change. The new read must
match the pinned root/file identity, copied bytes, size and mode. Its descriptor
size/mode/mtime must remain stable, and the root/entry names are rechecked after
reading. A failed check or canceled context refuses; there is no retry loop,
source rewrite or extra budget grant. Whole-archive and original expected-source
checks remain mandatory. The cost is one bounded extra read per regular member.
